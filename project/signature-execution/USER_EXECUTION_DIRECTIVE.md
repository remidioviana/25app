# PART II — APPLE DESIGN AWARDS: THE SIX EXCELLENCE DIMENSIONS

The six categories used by the 2026 Apple Design Awards must become mandatory reference dimensions in our internal quality reviews.

These categories are official Apple Design Awards categories. The numerical scorecard and execution requirements later in this document are our own additional standards, not official Apple judging rules.

## DIMENSION 01 — DELIGHT AND FUN

Create memorable, engaging, satisfying experiences.

Every application must contain meaningful moments of delight.

Delight can emerge from:

- An exceptionally smooth transition.
- An intelligent interaction that eliminates unnecessary work.
- A beautifully presented result.
- An unexpectedly useful AI recommendation.
- A natural gesture that makes a complex process effortless.
- A visual response that communicates success.
- An elegant detail that rewards exploration.

Delight must be appropriate to the application.

A serious legal compliance tool should not behave like a playful game.

A wellbeing application should not overwhelm users with excessive visual stimulation.

**CREATE DELIGHT THROUGH THOUGHTFULNESS, NOT DECORATIVE EXCESS.**

## DIMENSION 02 — INCLUSIVITY

Design exceptional experiences for people with different abilities, backgrounds, languages, and interaction preferences.

Every application must support relevant accessibility features:

- VoiceOver and TalkBack.
- Dynamic Type and Android font scaling.
- Sufficient contrast.
- Reduced-motion settings.
- Clear focus states.
- Accessible touch targets.
- Alternative interaction paths.
- Logical screen-reader navigation.
- Clear error messages.
- Appropriate support for Arabic and English, including right-to-left layouts where required.
- Controls that remain usable without complex gestures.

Accessibility must be integrated into the architecture from the beginning.

Do not treat it as a cosmetic final adjustment.

## DIMENSION 03 — INNOVATION

Each application must introduce at least one meaningful innovation in how users accomplish its primary purpose.

Innovation does not mean adding visual complexity.

It means creating a genuinely better way to interact with information, make decisions, or complete important tasks.

Every product needs a distinctive signature experience.

The innovation must be real and functional.

It must not exist only in a mockup, animation, or promotional description.

## DIMENSION 04 — INTERACTION

This is one of the most important dimensions for the entire portfolio.

Every application must demonstrate intuitive controls, effortless navigation, immediate feedback, and interactions tailored to its platform.

Implement:

- Direct manipulation.
- Natural gestures.
- Fluid transitions.
- Responsive controls.
- Contextual actions.
- Smooth state changes.
- Interactive visualizations.
- Clear navigation continuity.
- Meaningful haptics.
- Accessible interaction alternatives.
- Interruptible, reversible transitions where appropriate.

**INTERACTION QUALITY MUST BE AS IMPRESSIVE AS VISUAL QUALITY.**

A screen that looks extraordinary but behaves like a static image is unacceptable.

## DIMENSION 05 — SOCIAL IMPACT

Where applicable, demonstrate how the application improves real human outcomes.

This is especially important for government services, accessibility, sustainability, recruitment, legal assistance, healthcare-related information, and food redistribution.

Measure meaningful benefits when reliable data is available.

Do not fabricate impact statistics.

Design to reduce friction, improve access to information, support informed decisions, and enable users to accomplish worthwhile objectives.

## DIMENSION 06 — VISUALS AND GRAPHICS

Every application must achieve an exceptional standard of visual craftsmanship.

Require:

- Original and coherent art direction.
- Distinctive brand identities.
- Carefully chosen typography.
- Beautiful and functional imagery.
- Sophisticated interactive graphics.
- High-quality animations.
- Exceptional spacing and proportions.
- Refined visual hierarchy.
- Carefully integrated interface materials.
- Pixel-level attention to visual execution.

Do not confuse high visual complexity with high design quality.

An extraordinarily simple interface may demonstrate greater craftsmanship than a visually overloaded dashboard.

# PART IV — THE NON-NEGOTIABLE DYNAMIC INTERFACE STANDARD

## 1. EVERY SCREEN MUST RESPOND TO THE USER

The interface must never feel like a static presentation.

Every meaningful element must have appropriate working behavior.

A card should respond when it represents an actionable object.

A chart should support data exploration.

A slider should update real calculations.

A document highlight should reveal contextual findings.

A map should respond naturally to navigation.

A search field should produce actual relevant results.

A primary button should execute a real action or open a genuinely functional workflow.

An AI execution state should reflect actual system activity.

**NO DEAD BUTTONS. NO FAKE CONTROLS. NO STATIC CHARTS DISGUISED AS INTERACTIVE VISUALIZATIONS.**

## 2. APPLE-CALIBER MOTION ENGINEERING

Develop sophisticated motion systems appropriate to each application.

Use:

- Physically plausible spring animation.
- Fluid continuity between screens.
- Interactive transitions that follow gestures.
- Context-aware expansion.
- Smooth navigation changes.
- Responsive progress visualization.
- Purposeful depth and layering.
- Refined visual feedback.
- Appropriate native haptics.
- High-performance rendering.
- Animation cancellation and interruption where relevant.

Prefer platform-native animation mechanisms when they provide better integration.

Support accessibility settings that reduce motion or transparency.

Avoid unnecessary animation during serious or time-sensitive workflows.

Do not animate every element simply because animation is technically possible.

**THE BEST MOTION DESIGN MAKES COMPLEX INTERACTIONS FEEL NATURAL.**

## 3. DIRECT MANIPULATION

Users should feel that they are directly interacting with information rather than operating a complicated control panel.

Whenever appropriate, allow them to:

- Drag and reorganize meaningful objects.
- Swipe through contextual information.
- Expand and collapse visual structures.
- Zoom into documents and maps.
- Scrub through timelines.
- Manipulate chart selections.
- Compare scenarios through direct controls.
- Inspect visual evidence.
- Explore relationships interactively.
- Move between overview and detailed analysis without losing context.

Every custom gesture must have discoverable controls or accessible alternatives.

## 4. REAL-TIME AND CONTEXTUAL ADAPTATION

Interfaces should update in response to genuine changes in available information.

Examples include:

- Updated verified regulatory requirements.
- New published tender opportunities.
- Changes to user-controlled financial assumptions.
- Actual completion of authorized tasks.
- New verified shipment milestones.
- Updated restaurant search results.
- Changes in location-specific public schedules.
- Newly completed document analysis.

Use clear timestamps and source attribution where relevant.

Do not fabricate real-time activity.

## 5. APPLE LIQUID GLASS AND PLATFORM APPROPRIATE MATERIALS

Study Apple's modern material systems, including Liquid Glass where supported.

Understand their principles of depth, fluidity, layered presentation, focus, and contextual interaction.

Use platform-native materials only when they improve clarity and remain compatible with the product's identity.

Do not apply excessive transparency or glass effects to every screen.

Do not make 25 applications visually identical by forcing the same material treatment.

On Android, adopt appropriate native or custom material behavior that respects Android interaction conventions.

**APPLE-CALIBER CRAFTSMANSHIP MUST NOT BECOME APPLE VISUAL IMITATION.**

# PART VII — NATIVE iOS AND ANDROID QUALITY REQUIREMENTS

## iOS

Respect current Apple Human Interface Guidelines.

Use supported native capabilities, including SwiftUI or appropriate UIKit integrations where the architecture permits.

Study and apply relevant native motion, materials, gesture handling, accessibility, haptics, and fluid transitions.

Support Dynamic Type, VoiceOver, safe areas, native navigation behavior, and relevant system settings.

## Android

Deliver an equally refined experience.

Use Jetpack Compose or appropriate native integration where supported by the existing architecture.

Respect Android navigation patterns, predictive back behavior where supported, system insets, typography scaling, TalkBack, gesture handling, and relevant Material guidance.

## Cross-platform implementation

Use the existing architecture when it is capable of supporting the required experience.

If React Native, Flutter, or another supported framework is already in use, evaluate whether it can deliver the necessary native-quality interaction and performance.

Do not rebuild the entire project merely to change frameworks.

A cross-platform technology is acceptable if the result meets the required standards on both operating systems.

## Performance expectations

Aim for consistently smooth interactions, commonly targeting 60 frames per second where hardware and workload permit, with higher refresh rates on supported devices where practical.

Measure real performance instead of claiming perfection.

Reduce unnecessary rendering, excessive animations, battery consumption, memory pressure, and interface latency.

Use responsive loading and truthful progress states.

Maintain accessibility and stability even on less powerful supported devices.
